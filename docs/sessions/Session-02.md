# Task 1 – Understanding SDLC

The Software Development Life Cycle (SDLC) is a structured process followed by software companies to build high-quality applications. Instead of directly writing code, every project follows a series of planned phases.

### Seven Phases of SDLC

1. Requirement Gathering – Understand the client's needs.
2. Requirement Analysis – Analyze and refine the requirements.
3. System Design – Plan the architecture, database, APIs, and UI.
4. Development – Write the application code.
5. Testing – Verify that the application works correctly.
6. Deployment – Release the application for users.
7. Maintenance – Fix bugs, improve features, and support users.

# Task 3 – Understanding the SRS Sections

An SRS (Software Requirements Specification) is the blueprint of the project. It clearly explains what the system should do before development begins.

Key understanding:

* **Introduction:** Basic information about the project.
* **Project Overview:** Overall description of the application.
* **Problem Statement:** The business problem being solved.
* **Objectives:** Goals the application should achieve.
* **Scope:** Features included in the project.
* **Stakeholders:** People involved in or using the system.
* **Functional Requirements:** Features the system must provide.
* **Non-Functional Requirements:** Performance, security, reliability, scalability, and usability requirements.
* **Assumptions:** Conditions assumed to be true during development.
* **Constraints:** Technical or business limitations.

# Key Learning

Professional software development starts with planning and documentation, not coding. The SRS helps developers, testers, designers, and clients share the same understanding of the project, reducing confusion and future changes.
